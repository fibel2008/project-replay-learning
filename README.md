# project-replay-learning

在进厂实习前，用真实工程流程做出一个答辩/面试绝不露馅的个人项目——以架构清晰的真实开源项目为模板，由 AI 逆向构造「MVP → 逐步迭代」的开发历程，引导学习者亲手「重放」并迁移到自己的项目中。

---

## 一、当前状态

- **阶段**：设计阶段，已出大致工作流，待分模块逐步深入

## 二、核心理念

1. **以实践为核心，在模拟工程的背景下边做边学，了解简化工作场景下的工作流程。**
2. **鼓励试错，在反复尝试中建立对正确答案的印象，从而理解自己的想法和原项目之间的差距，并从中进行学习。**
3. **鼓励“先做起来再说”，即使没有技术背景，也可以通过自然语言描述，来加深未来编程知识学习的理解。**

## 五、工作流介绍

采用**手动多对话协作**：仅有一个「总对话」把控全局与验收，每个阶段开启一个独立的「阶段推进对话 X」专注教学，切换时从仪表盘复制启动 Prompt。

```text
[总对话] 0 初始化（仅一次）      
│      
▼      
┌──► A 发布需求（总对话）      ──► 发布 PRD X、创建空学习记录      
│        │      
│        ▼      
│    B 阶段学习（阶段对话 X）   ──► B1 架构讲解与用户设计文档 → B2 编码学习与调试 → Git 提交      
│        │      
│        ▼      
│    C 学习验收（总对话）      ──► 追问知识点 + 验证「项目重写」可跑通（双过才通过）      
│        │      
│        ▼      
│    D 迁移练习（可选）        ──► 发布 PRD X'，在「自行编码」中实践（可跳过）      
│        │      
│        ▼      
└─── E 迁移验收（总对话）      ──► 仅验功能实现 → 进入阶段 X+1
```


| 阶段             | 执行者          | 核心动作                                                                                              | 关键产出                               |
|--------------------|--------------------|-----------------------------------------------------------------------------------------------------------|--------------------------------------------|
| **0 初始化**    | 总对话          | 选模板项目、逆向规划路径、搭目录与依赖、选迁移题、生成总纲                   | 总纲、工作区目录                   |
| **A 发布需求** | 总对话          | 发布本阶段新增需求 PRD X，创建空学习记录                                                 | PRD X、空学习记录                    |
| **B 阶段学习** | 阶段对话 X     | 讲架构 → 用户复述设计文档 → 拆小块双路线编码学习 → 重写调试 → Git 提交 | 设计文档、重写代码、阶段记录 |
| **C 学习验收** | 总对话          | 追问知识点 + 验证「项目重写」代码能跑通                                                 | 阶段通过判定                         |
| **D 迁移练习** | 总对话 + 用户 | 发布 PRD X'，在「自行编码」中模仿实现（可选，允许 AI 辅助、无指引）           | 个人迁移项目代码                   |
| **E 迁移验收** | 总对话          | 检查 X' 功能是否实现，通过后推进至下一阶段 `A(X+1)`                                    | 状态流转                               |


## 六、推进规则

1. **（assistant）对话开始时，检查工作区内有没有尚未提交的git，如果有则提醒用户提交。**
2. **（assistant）当新增/修改文件时，不由ai做git管理，也不用在乎git颗粒度。**
3. **（assistant）在每次新增/修改完所有文件后，即完成任务后，在发送消息的最开头，单独写一段内容：描述ai在本轮中完成了什么任务，并提醒用户进行git管理。**
4. **（user）模块结束后与模块开始前，先阅读MANAGEMENT文件中“项目管理核心心法速查"板块内容。**
