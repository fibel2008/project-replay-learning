# 01 项目信息确认（重构版）

> 依据：`docs/验证实践学习_Python学习Skill_项目规划.pdf`、`docs/项目规划记录.pdf`
> 状态：第一轮审问完成（2026-11-19）
> 旧版设计已归档至 `docs/archive/`，不再参考。

## 一、定位

| 项 | 结论 |
|---|---|
| 第一版用户 | 先给自己用，验证「实践 → 学习」方法；验证成功后再做成通用产品 |
| 用户编程起点 | 不限水平，由「代码路线 / 自然语言路线」自动适配 |
| 运行平台 | 通用 Agent Skills 格式，兼容 Claude Code / Cursor / Gemini CLI / Antigravity 等 |
| 多对话实现 | 用户手动开新对话，从仪表盘复制启动 prompt；各对话靠工作台文件传递状态 |

## 二、初始化（步骤 0）

| 项 | 结论 |
|---|---|
| 模板项目选择 | **待讨论**。初步想法：同时支持三种方式——用户指定 + AI 评估、AI 按兴趣推荐、内置精选清单 |
| 开发路径依据 | 只看最终代码，AI 按「MVP → 逐步加需求」的理想顺序重新构造（不依赖 Git 历史） |
| 阶段粒度 | 不设上限，由 AI 按项目大小决定 |
| 总纲可改性 | 学习目标和项目范围不可更改；开发路径可由总对话修订，并留下修订记录 |
| 迁移项目题目 | 初始化时由 AI 推荐几个与原项目「结构相似、领域不同」的题目，用户选一个或自拟 |

## 三、阶段学习（步骤 B，阶段推进对话）

| 项 | 结论 |
|---|---|
| 设计文档 | AI 讲完架构后，用户用自己的话复述成设计文档 |
| 代码路线揭晓 | 逻辑正确后同样揭晓原代码，对比写法差异（命名、结构、惯用法） |
| 卡住时的引导 | **待讨论**（需详细设计提示分级与兜底） |
| 项目重写 | 每学完一小块，就把这一块写进「项目重写」 |

## 四、验收与迁移（步骤 C / D / E）

| 项 | 结论 |
|---|---|
| 学习验收 C | 追问知识点 + 验证「项目重写」代码能跑通，两者都过才通过 |
| 迁移验收 E | 只看功能是否实现 |
| 迁移可选性 | 可以自由跳过，不记录 |

## 五、工作台、Git 与 skill 结构

| 项 | 结论 |
|---|---|
| 记录格式 | 记录类用 Markdown；另配一个小 JSON 状态文件记录当前阶段和步骤 |
| 仪表盘 | **搁置**。初步想法：静态 HTML，数据来自 JSON 文件 |
| Git 范围 | 「项目重写」「自行编码」各自独立一个仓库；工作台不纳入 Git |
| skill 结构 | 一个 skill，内部按「总对话 / 阶段推进对话」拆分参考文件，由启动 prompt 指定模式 |

## 六、验证计划

| 项 | 结论 |
|---|---|
| 试点项目 | 未定，由 AI 推荐候选 |
| 成功标准 | 学完后不看参考，能独立写出迁移项目的下一个需求 |
| 第一版范围 | 一次性做完整版 |

## 七、待讨论 / 搁置清单

1. 模板项目选择：三种方式如何共存、评估标准是什么
2. 卡住时的引导：提示分级、何时给答案、如何记录错误
3. 仪表盘形态与数据结构
4. 源码很大时如何限制对话使用的范围、如何切块（规划中已搁置）
5. 框架合理性、各阶段的具体设计（规划中已搁置）
6. skill 自身的文件结构（区别于用户学习目录）
7. 试点项目候选推荐
