## 一、模块概括

### 1. 定位与核心目标
本模块定义阶段推进对话（阶段 B）中，当学习者在实现代码或描述自然语言逻辑时**出现错误、思路盲区或完全卡住**时，AI 的引导边界与兜底策略。核心目标是在「避免 AI 沦为直接代写工具」与「避免学习者陷入无意义死循环而挫败弃坑」之间取得平衡，确保学习者经历完整的**尝试 → 暴露盲区 → 反思 → 修正**闭环。

### 2. 已有共识（来自既有规划）
- **不直接给答案**：出现问题时只给方向，通过提问、举反例、提示可能缺少的知识背景来引导。
- **概念创造机制**：当用户因缺乏编程概念而完全想不出设计时，AI 用问题「逼出需求」，从而自然引出该概念。
- **分阶段递进**：原规划提出「提示 → 类比 → 解答」的递进方向，且期间穿插提问。
- **错题留痕**：在编码实践学习中出错的地方，需在「阶段 X 学习记录」中重点突出，供阶段 C 验收追问使用。

### 3. 补充设计草案：四级提示阶梯（L1–L4）与兜底闭环

为防止 AI 引导过早泄题或过度兜圈子，建议将卡壳引导标准化为四级递增阶梯：

| 级别 | 触发条件 | AI 行为 | 禁止行为 |
|---|---|---|---|
| **L1 反例与追问** | 首次出现逻辑偏差或边界遗漏 | 构造一个具体输入/场景作为反例，追问「按你的写法/描述，这里会发生什么？」 | 不指出具体错在哪一行、不给修复方案 |
| **L2 方向与概念提示** | L1 后仍无法定位，或明显缺少前置概念 | 点出缺失的知识背景或概念名称（如「这里涉及可变对象的引用传递」），用生活化类比说明，引导用户再试 | 不给现成代码片段 |
| **L3 骨架与伪代码提示** | 连续受阻或明确表示「知道概念但不知如何落笔」 | 给出最小结构提示（函数签名、步骤骨架或关键 API 名称），留空核心逻辑由用户补全 | 不直接替用户写完整个小块 |
| **L4 兜底揭晓 + 复述检验** | 触发熔断阈值（如同一小块卡壳超过 N 轮）或用户主动申请「看答案」 | 揭晓该小块的最小可行逻辑/原项目实现并逐行讲解；**强制要求用户合上参考后用自己的话复述或独立默写一遍**才算过关 | 不允许「看完说懂了」直接跳过 |

## 二、待讨论问题

### Q1. 提示阶梯的升级触发机制：自动计数 vs 用户主动要提示？
- **背景**：如果完全靠 AI 自动判断何时从 L1 升到 L2/L3，不同模型的耐心尺度不一致；如果全靠用户要提示，新手可能不知道自己已经陷入死胡同。
- **备选方案**：
  - **方案 A（混合触发，推荐）**：同一问题连续 2 轮无实质进展自动升一级；同时允许用户随时输入明确口令（如「给点提示」「直接看答案」）手动升档。
  - **方案 B（纯回合计数）**：严格规定每级最多 1~2 轮，超时自动降维兜底。
  - **方案 C（纯用户驱动）**：AI 默认停留在 L1，只有用户主动求助才进入 L2/L3/L4。
- **待拍板点**：确定默认升级节奏，以及用户主动要答案时是否需要 AI 先做一次「二次确认」（防冲动直接看答案）。

### Q2. 「代码路线」与「自然语言路线」的卡壳处理是否需要差异化？
- **背景**：走代码路线的用户可能卡在**语法/API 细节**（并非逻辑错）；走自然语言路线的用户通常卡在**抽象建模/边界条件**。
- **待拍板点**：
  - 代码路线遇到纯语法报错（如 `IndentationError`、`TypeError`）时，是否跳过 L1 反例追问，直接给语法解释或报错定位指引，把苏格拉底式追问留给**逻辑与架构问题**？
  - 代码路线卡壳太久时，是否支持中途「降级」切回自然语言路线先理清思路，再回来写代码？

### Q3. 触发 L4（兜底揭晓答案）后的「防假懂」校验标准是什么？
- **背景**：若用户靠 L4 看了答案直接继续，容易退化成「看了一遍以为会了」。
- **备选方案**：
  - **轻量校验**：要求用户用自己的话总结「刚才卡在哪 + 核心思路是什么」，写进学习记录后继续。
  - **重写校验**：要求用户不看提示，在「项目重写」里把这一小块独立敲出来并跑通，再进入下一块。
- **待拍板点**：选择哪种校验力度，以及 L4 兜底的小块是否自动标记为**阶段 C 必考题**？

### Q4. 「错误记录」的粒度与记录标准是什么？
- **背景**：规划要求在「阶段 X 学习记录」中「突出第三步错的地方」，但一次调试可能包含 10 次小拼写错误和 2 次关键逻辑盲区。
- **待拍板点**：
  - 哪些错误值得写入学习记录？（例如：仅记录触发 L2 及以上的逻辑/设计/概念错误，忽略拼写与低级语法笔误？）
  - 记录字段是否需要标准化？（如：`卡点现象` / `根因（缺失概念或思维盲区）` / `最终修正方式` / `触发提示级别`）

### Q5. 情绪与节奏保护：防挫败机制要不要做？
- **背景**：面对复杂模块时，连续多轮被反例追问容易引发学习者的烦躁或自我怀疑。
- **待拍板点**：当用户同一阶段多次触发 L3/L4 时，AI 是否需要主动建议「把当前小块再拆细一档」或「先暂停复盘前置知识」，而不是硬推原定拆块粒度？
