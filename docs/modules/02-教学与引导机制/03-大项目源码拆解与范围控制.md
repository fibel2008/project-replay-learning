## 一、核心目标

解决真实开源项目体量庞大、直接拆块易丢失架构整体性的问题，通过逆向构造「MVP → 逐步加需求」的演进路径并限制单轮对话可见的源码范围，保证学习既连贯又不超出上下文承载能力。

## 二、已有共识（来自已有规划）

- **逆向构造原则**：只看最终代码，由 AI 按「MVP → 逐步加需求」的理想开发顺序重新构造开发路径（不依赖 Git 历史）。
- **保持架构完整性**：限制拆块方法——依照真实开发流程（需求 → PRD → 设计架构 → 设计文档 → 编码实现 → 调试）逐步演进，而非零散按文件切碎。
- **阶段粒度**：不设上限，由 AI 按项目大小决定。
