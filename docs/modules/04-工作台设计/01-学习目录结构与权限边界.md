## 一、模块目标与范围边界

### 1.1 核心目标

明确用户本地学习主文件夹的**四分区物理结构、纯英文命名规范、Git 边界与三方读写权限矩阵**，确保：

- 原项目参照（`origin/`）永久只读不被污染；
- 重写代码（`replay/`）与个人迁移代码（`personal/`）完全隔离；
- 工作台（`workbench/`）清晰承载跨对话状态与过程文档，杜绝多对话越权覆盖。

### 1.2 本模块范围（In Scope）

- 完整物理目录树（可直接照搬建目录）及文件/目录命名约定。
- 四分区的 Git 纳入/排除边界。
- **总对话 / 阶段推进对话 / 用户** 三方对各目录的读（R）、写（W）、创建（C）、删除（D）权限矩阵与防越权红线。

### 1.3 本模块不管（Out of Scope）

- ❌ `state.json` 的具体 Schema 字段与交接协议（详见 `04-02`）。
- ❌ 总纲、项目记录、学习记录、用户设计文档的正文模板（详见 `03-01`、`03-02`、`01-03`）。
- ❌ Git 详细提交规范、分支策略与里程碑标签（详见 P1 `04-04`）。
- ❌ 仪表盘的交互与可视化设计（详见 P2 `04-03`）。

## 二、物理目录树与命名规范

### 2.1 目录命名约定

1. **纯英文、全小写、不带数字序号**：所有顶层分区与固定目录均使用全小写英文（必要时用连字符 `kebab-case`），不使用中文路径或空格，避免跨平台（Windows/macOS/Linux）大小写差异及 CLI / Python 模块导入兼容问题。
2. **阶段文件统一两位数补零**：按阶段生成的文件统一使用 `stage-<NN>-<type>.md`（如 `stage-01-prd.md`、`stage-02-design.md`），保证按文件名排序即等于阶段顺序。
3. **根目录位置**：学习主文件夹 `<learning-workspace>/` 由用户在阶段 0 指定（建议新建文件夹，命名如 `replay-<project-name>/`）。


### 2.2 完整物理目录树（可直接照搬创建）

```text
<learning-workspace>/                 # 用户指定的本地学习主文件夹（不建 Git 仓库）        
├── origin/                           # [分区 1] 原项目备份（只读参照，不纳入 Git）        
│   └── <原项目完整源码目录...>       # 阶段 0 拷入或克隆后移除原 .git，永久只读        
│        
├── replay/                           # [分区 2] 项目重写（独立 Git 仓库，核心学习区）        
│   ├── .git/                         # 独立 Git 仓库（仅管理 replay/）        
│   ├── .gitignore        
│   ├── docs/                         # 阶段 B1 用户复述并编写的设计文档        
│   │   ├── stage-01-design.md        # 命名约定：stage-<NN>-design.md        
│   │   └── stage-02-design.md        
│   └── <按阶段逐步重写的源码与测试...>        
│        
├── personal/                         # [分区 3] 自行编码 / 迁移练习（独立 Git 仓库）[P1 预留]        
│   ├── .git/                         # 独立 Git 仓库（仅管理 personal/，与 replay/ 隔离）        
│   ├── .gitignore        
│   └── <用户个人迁移项目源码与文档...>        
│        
└── workbench/                        # [分区 4] 工作台（不纳入 Git，承载状态与记录）        
    ├── state.json                    # 机器可读状态文件（Schema 见 04-02）        
    ├── dashboard.md                  # MVP 状态概览与启动 Prompt 入口（P2 扩展为 dashboard/ 文件夹）        
    ├── project-records/              # 项目记录（全局总纲、各阶段 PRD 与阶段蓝图）
    │   ├── master-plan.md            # 总纲文档（模板见 03-01）
    │   ├── stage-01-prd.md           # 阶段 X 需求文档（命名约定：stage-<NN>-prd.md）
    │   ├── stage-02-prd.md
    │   └── stage-maps/               # 各阶段目录蓝图与轻量参照锚点（见 02-03）
    │       ├── stage-01-map.md       # 命名约定：stage-<NN>-map.md
    │       └── stage-02-map.md
    └── learning-records/             # 学习记录（各阶段学习过程与卡点）        
        ├── stage-01-log.md           # 阶段 X 学习记录（命名约定：stage-<NN>-log.md）        
        └── stage-02-log.md
```

> 
> **MVP（P0）与 P1/P2 占位说明**：
> 
> 
> - `personal/` 属于 **P1（阶段 D/E 迁移练习）**；在 P0 最小闭环初始化时，可仅建空目录占位（暂不初始化 `.git`），待启用迁移练习时激活。
> - `workbench/dashboard.md` 为 **P0（MVP）** 极简文本替代方案；**P2（`04-03`）** 引入静态 HTML 仪表盘时，在 `workbench/` 同级新增 `dashboard/` 即可，不破坏现有结构。
> 

### 2.3 Git 边界划分（仅界定归属，不展开提交规范）


| 目录                                       | 是否纳入 Git | 说明                                                                               |
|:---------------------------------------------|:----------------:|:-------------------------------------------------------------------------------------|
| `<learning-workspace>/`（根目录） | ❌ 否          | 禁止在根目录执行 `git init`，避免嵌套仓库冲突                       |
| `origin/`                                    | ❌ 否          | 只读参照快照；若通过 `git clone` 获取，阶段 0 须删除 `origin/.git` |
| `replay/`                                    | ✅ 独立仓库 | 管理用户按阶段重写的代码及 `replay/docs/` 下的设计文档            |
| `personal/`                                  | ✅ 独立仓库 | 管理用户个人迁移项目，与 `replay/` 完全独立（P1 启用）           |
| `workbench/`                                 | ❌ 否          | 存放本地运行态状态、过程记录与仪表盘，不纳入代码仓库       |

## 三、角色 × 目录权限边界矩阵

### 3.1 角色与权限图例

- **三方角色**：- **总对话（Master Chat）**：负责阶段 0（初始化）、A（发布需求）、C（学习验收）、D/E（迁移练习与验收，P1）及路径修订。
- **阶段推进对话（Stage Chat X）**：仅负责单阶段 B（B1 架构讲解与设计文档审阅、B2 编码学习与调试辅导）。
- **用户（User）**：学习者本人，拥有本地文件物理控制权，但按约定遵循以下协作规范。
- **权限符号**：`R` = 读取，`W` = 修改，`C` = 创建，`D` = 删除，`-` = 禁止访问。

### 3.2 权限边界表


| 目录 / 文件路径                                | 总对话（Master）                                          | 阶段推进对话（Stage X）                           | 用户（User） | 关键约束说明                                                                                                                   |
|:-----------------------------------------------------|:--------------------------------------------------------------:|:---------------------------------------------------------:|:----------------:|:-------------------------------------------------------------------------------------------------------------------------------------|
| `origin/`                                            | `R`（阶段 0 一次性 `C`）                                | `R`                                                       | `R`              | **初始化后永久只读**，三方均严禁修改或删除                                                                        |
| `replay/`（源码与测试）                       | `R`（阶段 0 可 `C` 脚手架）                            | `R/C`（严禁默认代写,可创建脚手架空文件） | `R / W / C / D`  | 用户为核心编码主体；阶段对话仅读代码排查与引导（特殊路线兜底边界见 `02-01`/`02-02`）               |
| `replay/docs/stage-<NN>-design.md`             | `R`                                                            | R/W/C                                                     | `R / W / C / D`  | 阶段 B1 由用户亲自复述, 文件可根据用户复述内容生成                                                             |
| `personal/`（P1）                                  | `R`（阶段 0 可 `C` 空目录；阶段 D 可按需辅助） | `-`                                                       | `R / W / C / D`  | 阶段推进对话无权访问，避免上下文串扰                                                                               |
| `workbench/state.json`                               | `R / W / C`                                                    | `R/W`                                                     | `R`              | 主对话和推进对话均可记录状态文件                                                                                     |
| `workbench/dashboard.md`                             | `R / W / C`                                                    | `R`                                                       | `R`              | 随状态变更由总对话统一刷新                                                                                              |
| `workbench/project-records/master-plan.md`           | `R / W / C`                                                    | `R`                                                       | `R`              | 总对话阶段 0 创建；仅总对话可修改总纲全文（软约束不回改已完成阶段）、取消路径修订记录表    |
| `workbench/project-records/stage-<NN>-prd.md`  | `R / W / C`                                                    | `R`                                                       | `R`              | 总对话阶段 A 创建并发布；阶段对话严禁篡改需求范围                                                             |
| `workbench/project-records/stage-maps/stage-<NN>-map.md` | `R / W / C`                                          | `R`                                                       | `R`              | 总对话阶段 0 生成，记录各阶段预期目录结构（硬性核验基准）与轻量参照锚点；阶段对话只读严禁修改               |
| `workbench/learning-records/stage-<NN>-log.md` | `R / C`                                                        | `R / W`（仅限当前阶段 `X`）                       | `R / W`          | 总对话阶段 A 建空文件、阶段 C 只读验收；阶段对话 X 仅可读写本阶段记录，严禁改历史阶段或删除 |

## 四、防越权红线与兜底规则

1. **红线 1 — `origin/` 不可变铁律**：阶段 0 完成拷入并清理原 `.git` 后，`origin/` 进入永久只读状态。任何对话在任何情况下均不得修改、格式化、重命名或删除其中文件；若用户不慎误改，应通过重新拉取/恢复原项目修复。
2. **红线 2 — 阶段隔离与防跨区污染**：阶段推进对话 X 的写入范围严格限定在 `workbench/learning-records/stage-<X>-log.md`（及 `04-02` 明确授权的状态字段），严禁修改其他阶段记录、PRD、总纲，且完全禁止读取或修改 `personal/`。
3. **红线 3 — 单权威写入防覆盖**：`master-plan.md`、`stage-<NN>-prd.md`、`stage-maps/stage-<NN>-map.md`、`dashboard.md` 仅允许由总对话写入，避免多对话并行导致文件覆盖冲突。
