## 一、模块目标与范围边界

### 1.1 核心目标

在「手动多对话协作（总对话 + 各阶段推进对话）」模式下，以 `workbench/state.json` 为轻量级单一状态源，配合 `workbench/` 下的 Markdown
过程文档，建立确定性的**跨对话状态流转与双向交接协议**，防止上下文割裂、进度错乱或跨对话越权覆盖。

### 1.2 本模块范围（In Scope）

- 定义 `workbench/state.json` 的完整 Schema（v1）、字段说明与合法示例。
- 定义 MVP 主干状态机流转规则（`A → B1 → B2 → C → 下一阶段 / 完成`），并为 P1 阶段 `D / E` 预留扩展位。
- **闭环 `04-01` 遗留决策**：锁定总对话与阶段推进对话对 `state.json` 的**主从分工写入权边界**。
- 定义多对话双向交接清单（交出前检查 + 冷启动必读校验）与轻量防错位校验规则。

### 1.3 本模块不管（Out of Scope）

- ❌ 启动 Prompt 具体文案模板与双模式路由逻辑（详见 `#14` `05-02`）。
- ❌ 总纲、PRD、学习记录、设计文档的 Markdown 正文模板（详见 `#03`、`#04`、`#07`）。
- ❌ 阶段 `D / E`（迁移练习与验收）的详细业务流程（详见 P1 `01-06`、`01-07`）。
- ❌ 复杂异常流与路径修订流程（详见 P1 `01-08`）。
- ❌ 仪表盘的展示排版与前端实现（详见 P2 `04-03`）。

## 二、核心设计约定

1. **阶段 0 不入状态表**：阶段 0（初始化）是一次性建仓与规划动作，**不作为阶段记录在 `state.json` 中**。阶段 0 完成总纲规划后，直接生成包含 `1..N` 个阶段的初始 `state.json`，并将当前指针落在第 1 阶段的 `A` 步骤。
2. **每阶段固定子步骤结构**：每个阶段 `X` 下统一设 `A`、`B1`、`B2`、`C` 四个 MVP 步骤（逻辑对应 `A_X / B1_X / B2_X / C_X`；P1 启用迁移练习时按需追加 `D`、`E`）。
3. **轻量级状态颗粒度**：`state.json` 只追踪到「阶段 + 大步骤（`A / B1 / B2 / C`）」，**不记录** B2 内部做到第几个编码小块（chunk）的细粒度进度——细粒度进度与学习细节统一落在 `workbench/learning-records/stage-<NN>-log.md` 中，避免 JSON 膨胀与双写不同步。
4. **主从分工写入**：总对话与阶段推进对话均拥有 `state.json` 的写入权，但**严格按字段与归属权（`owner`）隔离**，同一时刻仅允许当前 `owner` 写入对应字段。

### 3.2 字段说明与枚举定义


| 字段路径            | 类型  | 必填 | 枚举值 / 格式约束                              | 说明                                                              |
|:------------------------|:-------:|:------:|:------------------------------------------------------|:--------------------------------------------------------------------|
| `schema_version`        | string  | ✅    | `"1.0"`                                               | Schema 版本号，便于后续演进兼容                         |
| `project.name`          | string  | ✅    | 英文 `kebab-case`                                   | 当前重放学习的项目标识名                                |
| `project.origin_source` | string  | ✅    | 自由文本 / 仓库名                              | `origin/` 来源简述                                              |
| `project.total_stages`  | integer | ✅    | `>= 1`                                             | 总纲规划的阶段总数 `N`（与 `stages.length` 一致）     |
| `project.status`        | string  | ✅    | `"in_progress"`                                       | `"completed"`                                                       | 全局学习项目状态                         |
| `project.created_at`    | string  | ✅    | ISO 8601 时间戳                                    | 阶段 0 初始化完成时间                                      |
| `current.stage`         | integer | ✅    | `1 .. total_stages`                                   | 当前活跃阶段编号 `X`                                        |
| `current.step`          | string  | ✅    | `"A"`                                                 | `"B1"`                                                              | `"B2"`                                           | `"C"` *(P1 预留 `"D"`                               | `"E"`)* | 当前活跃步骤 |
| `current.owner`         | string  | ✅    | `"master"`                                            | `"stage"`                                                           | 当前拥有推进权与写入权的对话角色 |
| `stages[]`              | array   | ✅    | 长度等于 `total_stages`                           | 按 `stage` 升序排列的各阶段状态列表                    |
| `stages[].stage`        | integer | ✅    | `1 .. total_stages`                                   | 阶段编号 `X`                                                    |
| `stages[].title`        | string  | ✅    | 简短中文/英文标题                             | 与总纲一致的阶段名称                                      |
| `stages[].status`       | string  | ✅    | `"pending"`                                           | `"in_progress"`                                                     | `"done"`                                         | 该阶段整体状态                                 |
| `stages[].steps`        | object  | ✅    | 固定键 `A`, `B1`, `B2`, `C` *(P1 可选 `D`, `E`)* | 各子步骤状态，取值：`"pending"`                           | `"in_progress"`                                  | `"done"` *(P1 阶段 `D/E` 额外允许 `"skipped"`)* |
| `stages[].artifacts`    | object  | ✅    | 相对 `<learning-workspace>/` 的路径        | 固定键 `prd`、`map`、`design`、`log`，供冷启动直接定位文件 |
| `meta.updated_at`       | string  | ✅    | ISO 8601 时间戳                                    | 最近一次写入时间                                            |
| `meta.last_updated_by`  | string  | ✅    | `"master"`                                            | `"stage-<NN>"`                                                | 最近一次写入的对话标识                |

## 四、状态机流转规则与写入权边界

### 4.1 MVP 主干状态流转表

```text
[阶段 0 初始化落盘]  
│  
▼ (current: stage=1, step=A, owner=master)  
┌──► [A_X 发布需求]        (master)  ──► A=done, current=(X, B1, stage)  
│         │  
│         ▼  
│    [B1_X 架构与设计文档]  (stage)   ──► B1=done, B2=in_progress, current=(X, B2, stage)  
│         │  
│         ▼  
│    [B2_X 编码学习与调试]  (stage)   ──► B2=done, current=(X, C, master)  
│         │  
│         ▼  
│    [C_X 学习验收]        (master)  
│      ├── 未通过（需返工） ──────────► B2=in_progress, C=pending, current=(X, B2, stage)  
│      └── 双过（阶段通过） ──────────► C=done, stage.status=done  
│            ├── X < total_stages ──► current=(X+1, A, master) ──┘  
│            └── X == total_stages ─► project.status=completed
```

>
> **P1 扩展预留说明**：当 P1 启用阶段 D/E 时，阶段 C 通过后不直接跳至 `X+1`，而是流转至 `current=(X, D, master)`（跳过迁移时标记 `D="skipped", E="skipped"` 再进 `X+1`）。
>

### 4.2 主从写入权边界（正式锁定 `04-01` 遗留项）


| 角色                                | 允许写入时机                                         | 允许修改的字段范围                                                                                                                                                                                                                                                                                                                                                                             | 严禁操作                                                                                                                             |
|:--------------------------------------|:-----------------------------------------------------------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|:-----------------------------------------------------------------------------------------------------------------------------------------|
| **总对话（Master）**             | 阶段 0 初始化，或 `current.owner == "master"`       | 全量创建（阶段 0）；更新 `project.status`、`project.total_stages`（路径修订时）、`current.*`、`stages[X-1].status`、`stages[X-1].steps.{A, C}`（及返工重置 `B2`）、`meta.*`                                                                                                                                                                                               | 严禁在 `current.owner == "stage"` 时静默覆盖阶段对话正在推进的 `B1/B2` 状态（除非用户显式要求强制回退） |
| **阶段推进对话 X（Stage X）** | 仅当 `current.stage == X` 且 `current.owner == "stage"` | **仅限**：<br>1. `stages[X-1].steps.B1`（`pending → in_progress → done`）<br>2. `stages[X-1].steps.B2`（`pending → in_progress → done`）<br>3. `current.step`（`B1 → B2 → C`）<br>4. `current.owner`（仅在 `B2 == "done"` 交接验收时改为 `"master"`）<br>5. `meta.updated_at` 与 `meta.last_updated_by`（设为 `"stage-<NN>"`） | 严禁修改 `project.*`、`current.stage`、其他阶段条目、`steps.A`、`steps.C`、`artifacts.*` 或删除任何字段            |
| **用户（User）**                  | 仅应急人工修复                                      | 不建议手动编辑；若 JSON 损坏由总对话协助重建                                                                                                                                                                                                                                                                                                                                         | 避免直接手改破坏结构一致性                                                                                                  |

## 五、多对话双向交接协议（Handoff Protocol）

### 5.1 交接方向 1：总对话 → 阶段推进对话 X（`A → B1` 或 `C 返工 → B2`）

**① 总对话交出前检查（Pre-Handoff Checklist）**

- `workbench/project-records/stage-<NN>-prd.md` 已生成且非空；
- `workbench/learning-records/stage-<NN>-log.md` 已创建（首次为空模板；若为阶段 C 返工，已追加不通过原因与待修复项）；
- `workbench/state.json` 已更新：`steps.A = "done"`、`stages[X-1].status = "in_progress"`、`current = { stage: X, step: "B1" | "B2", owner: "stage" }`；
- `workbench/dashboard.md` 已刷新当前进度与阶段 X 启动提示。

**② 阶段推进对话 X 冷启动必读与校验（Cold-Start Checklist）**

1. 按顺序读取以下文件恢复上下文：
   1. `workbench/state.json`
   2. `workbench/project-records/master-plan.md`
   3. `workbench/project-records/stage-<NN>-prd.md`
   4. `workbench/project-records/stage-maps/stage-<NN>-map.md`（核对本阶段预期目录结构与参照锚点）
   5. `workbench/learning-records/stage-<NN>-log.md`（若为 B2 断点续传或 C 返工，重点读取已有进度与问题记录）
6. 执行准入校验：确认 `current.stage == X`、`current.owner == "stage"` 且 `current.step` 为 `"B1"` 或 `"B2"`；通过后将对应步骤置为 `"in_progress"` 开始教学。


### 5.2 交接方向 2：阶段推进对话 X → 总对话（`B2 → C`）

**① 阶段推进对话 X 交出前检查（Pre-Handoff Checklist）**

- `replay/docs/stage-<NN>-design.md` 已存在且非空（B1 产出）；
- `replay/` 下本阶段代码已完成调试并提醒用户完成 Git 提交（B2 产出）；
- `workbench/learning-records/stage-<NN>-log.md` 已补全本阶段学习记录、卡点与易错点；
- `workbench/state.json` 已更新：`steps.B1 = "done"`、`steps.B2 = "done"`、`current = { stage: X, step: "C", owner: "master" }`、`meta.last_updated_by = "stage-<NN>"`。

**② 总对话进入阶段 C 前就绪校验（Acceptance Readiness Check）**

1. 读取 `workbench/state.json`，确认 `current.stage == X`、`current.step == "C"`、`current.owner == "master"` 且 `steps.B2 == "done"`。
2. 核验关键交付物存在性：`replay/docs/stage-<NN>-design.md` 非空、`workbench/learning-records/stage-<NN>-log.md` 已有学习内容。
3. 校验通过后，将 `steps.C` 置为 `"in_progress"`，开始知识点追问与代码运行验收。


### 5.3 基础防错位与一致性校验（轻量兜底）


| 异常场景                                   | 检测条件                                                                                                         | 规定处理动作                                                                                                              |
|:-----------------------------------------------|:---------------------------------------------------------------------------------------------------------------------|:--------------------------------------------------------------------------------------------------------------------------------|
| **开错阶段对话**                         | 启动「阶段 X 对话」，但 `current.stage != X`                                                               | 立即停止推进，向用户汇报当前实际所处阶段与步骤，引导切回正确对话                                |
| **角色归属错位**                         | `current.owner == "master"` 时误开阶段对话；或 `current.owner == "stage"` 时在总对话请求直接验收 | 拒绝越权推进，明确提示当前应由哪一侧对话执行下一步                                                     |
| **B2 中途重开新对话（断点续传）** | 新开「阶段 X 对话」，且 `current.stage == X`、`current.step == "B2"`、`steps.B2 == "in_progress"`        | **视为合法续传**：不重置 `state.json`，直接读取 `stage-<NN>-log.md` 与 `replay/` 现状无缝接续       |
| **状态与交付物不一致**                | `state.json` 标记 `B2 == "done"`，但 `stage-<NN>-design.md` 缺失或 `stage-<NN>-log.md` 为空     | 总对话在阶段 C 启动前拦截，指出缺失交付物并提示返回补齐                                               |
| **写入安全约束**                         | 任意写入方更新 `state.json`                                                                                   | 必须**先读后写**，保留所有未修改字段，保证 JSON 合法并刷新 `meta.updated_at` 与 `meta.last_updated_by` |
